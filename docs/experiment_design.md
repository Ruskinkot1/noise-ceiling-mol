## Решение по формуле доли потолка (шаг 0.3)
Основная: `frac_ceiling = (RMSE_mean − RMSE_model) / (RMSE_mean − RMSE_floor)`.
- `RMSE_mean` — RMSE предсказания «среднее по train» на том же тесте (пишет scripts/04, столбец `rmse_mean`);
- `RMSE_floor = σ·sqrt(mean(1/n_docs))` по тест-молекулам (src/ncmol/ceiling.py);
- 0 = не лучше среднего, 1 = на потолке шума, >1 = подозрение на подгонку шума или утечку, <0 = хуже среднего.
Почему: понятная нулевая точка для обеих аудиторий; не зависит от масштаба pActivity.
Вспомогательные (в таблицах, не в заголовках): `frac_rmse = RMSE_floor/RMSE`, `frac_r2 = R²/R²_max`.
Метка теста шумная, поэтому потолок считается под набор тест-молекул (учёт n_docs); поправка на аттенюацию — TBD (W6).

## Честность сравнения (требование пользователя; обязательно в Methods/Limitations статьи)
1. Одинаковые данные, сплиты и сиды для всех моделей.
2. Одинаковый бюджет подбора гиперпараметров у ECFP+GBM/RF/MLP, GNN и «голов» над эмбеддингами.
3. Фундаментальные модели: только заморозка + голова, без дообучения; это явное ограничение.
4. Метка теста шумная: доля потолка + поправка на аттенюацию.
5. Риск против малых моделей: корпуса PubChem/ZINC могут содержать наши молекулы, даты отсечения могут быть «не проверено»; деконтаминация обязательна, оценка утечки = чистое vs неочищенное.
6. Парное сравнение по задачам с ДИ и поправкой на множественные сравнения; различия внутри шума так и называть.
