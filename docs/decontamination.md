## 1. Реестр «уже виденных» молекул (`data/registry/`, в git не идёт)
Формат `data/registry/<источник>.csv.gz`: `inchikey14, inchikey_full, smiles, source, url, downloaded`.
Структуры стандартизованы `ncmol.chem.standardize` (как датасет); полный InChIKey считается по стандартизованному SMILES.
`_status.csv` — HTTP-статус, размер, число строк по каждому источнику; `_raw/` — скачанные файлы; `_polaris_catalog.csv` — метаданные Polaris.

| Группа | Источник и проверка | Файлов | Уник. структур (полный ключ, сумма по файлам) |
|---|---|---|---|
| MoleculeNet | `https://deepchemdata.s3-us-west-1.amazonaws.com/datasets/<файл>`; все 11 ответили HTTP 200: ESOL (delaney-processed), FreeSolv (SAMPL), Lipophilicity, BACE, HIV, BBBP, Tox21, ClinTox, SIDER, ToxCast, MUV | 11 | 161958 |
| TDC | Harvard Dataverse `https://dataverse.harvard.edu/api/access/datafile/<id>`; id взяты из `tdc/metadata.py` (pytdc 1.1.15, скачан с PyPI, не установлен); все 40 ответили HTTP 200: все ADME и Tox наборы + HIV + 2 SARS-CoV-2 | 40 | 200524 |
| Polaris | Каталог метаданных открыт (`https://polarishub.io/api/v1/dataset`, 96 датасетов). Таблицы отдаются через storage-токен, polaris-lib требует OAuth-логин (код `polaris/hub/storage.py`), pip-установка lib на py3.13 не собралась (pyarrow) | 0 | не скачано |

Итого 362482 строк, 192953 уникальных InChIKey14, 202019 уникальных полных ключей (файлы пересекаются: MoleculeNet и TDC дублируют друг друга).

Не включено сознательно: TDC HTS Butkiewicz (по ~100-340 тыс. структур каждый), `herg_central`, BindingDB, DrugComb, QM, `chembl`/`zinc`/`moses` (корпуса, не бенчмарки);
MoleculeNet PCBA/QM9; MoleculeACE и Polaris-наборы (в основном ChEMBL, таблицы Polaris за логином) — **не проверено**, нужны ли и доступны ли напрямую (прямой URL MoleculeACE не проверялся).
Polaris-зеркала TDC (владелец `tdcommons`) дублируют уже включённый TDC.

## 2. Корпуса предобучения моделей
Не загружаются (PubChem 77M, PubChem+ZINC 1.1B). Записаны в `configs/model_cutoffs.yaml` (модель, корпус, дата, источник, флаги проверки).
Проверено (arXiv API, 2026-10-09): ChemBERTa-2 — препринт 2022-09-05, «up to 77M compounds from PubChem»; MoLFormer — arXiv 2106.09553, v1 2021-06-17, последнее обновление 2022-12-14, «1.1 billion molecules from PubChem and ZINC».
**Не проверено**: фактическая дата снимка PubChem/ZINC и отсечка обучающих данных у всех моделей (поле `training_cutoff: null`).
Правило эффективной отсечки: `training_cutoff` → иначе дата препринта (обучение не могло закончиться позже) → иначе сегодняшняя дата (самая поздняя возможная, «не проверено»).
Документ сохраняется, если `doc year` строго больше года отсечки (год отсечки включительно считается виденным: у года нет месяца).
Для `chemberta2_77m` отсечка 2022, для `molformer_xl` 2022; clean-набор по умолчанию берёт максимум по выбранным моделям.
Ограничение: фильтр по году документа не доказывает отсутствие молекулы в PubChem (ChEMBL-молекулы и вещества из старых документов могли попасть в PubChem независимо), он лишь отсекает документы, опубликованные до препринта. Прямая проверка пересечения с PubChem не делалась.

## 3. Шаги очистки (`02b_decontaminate.py`)
1. Точное совпадение по полному InChIKey, затем по InChIKey14 (стереоизомеры) — удаляются все измерения молекулы.
2. Близкие аналоги: Tanimoto ECFP4 (Morgan r=2, 2048 бит, биты) > порога (по умолчанию 0.8) к любой молекуле реестра. Ускорение: реестр отсортирован по числу бит, кандидаты вне окна `[t*a, a/t]` не считаются (для t=порог значения ≥ t точны, ниже — нижняя оценка).
3. Фильтр документов по году (см. выше); молекулы пересчитываются из оставшихся измерений (среднее по документам, `n_docs`, `first_year`).
Вывод: `data/processed_raw` (копия без очистки), `data/processed_clean` (+ `tasks.csv`, `decontam_loss.csv` — потери по задачам и шагам, `decontam_models.csv` — отсечка, флаг проверки и доля пересечения тест-молекул с известным обучающим набором модели; «н/д», если обучающий набор не в реестре; сейчас «н/д» у всех моделей, т.к. списки fine-tune-наборов в статьях не сверялись).
Утечка = разница метрик на raw и clean.

## 4. Пилот порога (случайные 5000 из 130113 уникальных молекул data/processed на момент запуска, 58 задач, seed 0)
Точные совпадения ik14: 403 (8.1%), полный ключ 345 (6.9%); главный источник — `tdc_herg_karim` (281, 5.6%), далее BACE, Lipophilicity, TDC HLM/RLM, ToxCast/Tox21.
Максимум Tanimoto у молекул без точного совпадения (n=4597): медиана 0.46, q90 0.67, q95 0.74, q99 0.84.

| порог | удалено сверх точных | суммарно с точными |
|---|---|---|
| >0.9 | 0.3% | 8.4% |
| >0.8 | 1.9% | 9.9% |
| >0.7 | 7.1% | 15.1% |
| >0.6 | 17.3% | 25.4% |
| >0.5 | 35.0% | 43.0% |

Обоснование 0.8: плотное тело распределения лежит в 0.3-0.6 (случайная близость drug-like молекул в ECFP4), хвост от 0.7 растёт слишком быстро (>0.7 уже теряет 7%, а типичные «одна замена» аналоги в ECFP4 дают ~0.6-0.75, т.е. это уже серия, а не копия); 0.8 — значение из плана, цена умеренная (1.9% молекул). Это обоснование эвристическое: порог не калибровался по утечке на реальной модели. Рекомендуется показать чувствительность результатов к порогам 0.7 / 0.8 / 0.9 (флаг `--threshold`). Выборка 5000 случайна, а не по задачам; пересечение по задачам различается.

## 5. Известные ограничения
- Реестр не содержит корпусов PubChem/ZINC и лент ChEMBL (сам датасет из ChEMBL; наборы вроде `herg_karim` ChEMBL-производные, поэтому пересечение с ними высоко).
- Стандартизация: наибольший фрагмент + нейтрализация, без таутомеров; различия таутомеров/зарядов могут пропускать совпадения.
- Фильтр по году документа — приближение (см. п. 2).

|---|---|---|

Итог: 154866 -> 8249 пар задача-молекула; после очистки ни одна из 58 задач не проходит порог реплицированных молекул (`decontam_loss.csv`, `tasks.csv`). Главный источник потерь — фильтр по году: большинство документов ChEMBL старше 2023. Если ограничиться только пересечением с бенчмарками (`--no-year`) или брать отсечку одной модели (`--models`, `--cutoff-year`), потери намного меньше (~10% молекул). Решение о том, нужен ли фильтр по году для всех моделей, остаётся за владельцем плана; отсечки выбраны консервативно (дата препринта, а не реально проверенная отсечка).
Время: ~16 мин на 4 ядрах при загруженной машине (стандартизация + InChI всех молекул, затем окно по числу бит).
